Ship a real e-commerce app, end to end — with the right AI tool at every commit.

This isn't a checklist. It's a 9-stage build pipeline — from first user story to post-launch monitoring — mapped for a React frontend and Node.js backend, with the AI tools, prompts, and pitfalls specific to each stage.

01 · Planning & Scoping

⏱ 2–4 daysOutput: PRD + backlog

Before any code, define exactly what "v1" means. Most solo e-commerce builds fail from scope creep, not from technical difficulty — this stage exists to prevent that.

Objectives

  • Define the store's niche, catalog size, and core buyer journey (browse → cart → checkout → order status).
  • Decide v1 scope vs. "later" — e.g., no multi-vendor, no subscriptions, no marketplace features at launch.
  • Choose the data model at a conceptual level: products, variants, orders, users, inventory.

Tasks

  • Write a one-paragraph product brief (who buys, what, why now)
  • List core user stories (guest checkout, account, order history, admin product upload)
  • Draw the data model: Product, Variant, Cart, Order, User, Payment
  • Cut scope: mark features as v1 / v2 / won't-build
  • Pick the stack specifics: React + Vite, Node + Express, DB choice, hosting target

Best AI tools

ChatGPT (GPT-5 thinking)Paid tier best
Strongest for turning a vague idea into a structured PRD and user-story backlog through back-and-forth questioning.
Alt: Claude (better long-context reasoning for full PRDs), Notion AI (if planning lives in Notion)
Claude
Best at holding the whole product brief in context while you iterate on scope cuts and data modeling in one thread.
Alt: Gemini (good if you're already in Google Workspace docs)
Whimsical AIFree tier
Generates flowcharts and ER-style diagrams from a text description — fast way to visualize the data model.
Alt: Excalidraw (manual, but pairs well with AI-drafted structure)

Prompt examples

Prompt 1 · PRD draft
Act as a senior product manager. I'm building a [niche] e-commerce store as a solo developer using React + Node.js. Ask me 8 clarifying questions one at a time about target customer, catalog size, and must-have checkout features, then write a one-page PRD with a scoped v1 feature list and a "not in v1" list.
Prompt 2 · Data model
Given this PRD: [paste PRD]. Propose a relational data model with tables for Product, ProductVariant, Cart, CartItem, Order, OrderItem, User, and Address. List each table's key fields and relationships, and flag any fields I'm likely missing for a real checkout flow.

Best practices

✓Write the "not in v1" list before the "in v1" list — it's the one that actually saves time.
✓Model orders and inventory before writing a single UI component.
✓Validate the idea against 3 real competitor stores before locking scope.

Common mistakes

✗Starting with the UI before the data model is settled.
✗Including multi-currency, multi-vendor, or subscriptions "just in case."
✗Skipping a written PRD because "it's just me building this."

Expected output

A one-page PRD, a prioritized backlog (v1/v2/cut), and a data model diagram — all before opening a code editor.

Efficiency tip

Keep the PRD conversation in one long-context thread (Claude or GPT-5 thinking) rather than starting fresh each time — it remembers earlier scope decisions and stops contradicting itself.

02 · Architecture & Design

⏱ 3–5 daysOutput: System diagram + repo scaffold

Decide how the React client, Node API, database, and third-party services (payments, images, email) talk to each other — before writing business logic.

Objectives

  • Choose monorepo vs. separate frontend/backend repos.
  • Pick the database (Postgres for relational order/inventory data is the common default) and ORM.
  • Define API contract: REST vs. GraphQL, auth strategy (JWT / session), and folder structure.

Tasks

  • Choose DB + ORM (e.g., PostgreSQL + Prisma)
  • Decide REST vs GraphQL for the storefront API
  • Sketch the system diagram: client, API, DB, payment provider, image CDN
  • Scaffold repo structure (client/, server/, shared types if using TypeScript)
  • Define auth strategy (JWT + refresh tokens, or session-based)

Best AI tools

Claude (Sonnet/Opus)
Reasons well about trade-offs (REST vs GraphQL, monorepo vs polyrepo) with your specific constraints, not generic advice.
Alt: ChatGPT o-series for deep reasoning on scaling trade-offs
v0 by Vercel / Claude Artifacts
Can scaffold a working repo skeleton (folders, config files, base routes) directly from a description.
Alt: Cursor with a "generate project structure" prompt
Eraser.io AI
Purpose-built for system/architecture diagrams from plain-text descriptions — cleaner than generic diagram tools for this use.
Alt: Mermaid (free, code-based, works in most AI chat tools)

Prompt examples

Prompt 1 · Architecture decision
I'm building an e-commerce app: React (Vite) frontend, Node.js + Express backend, solo developer, expecting under 10k monthly users at launch. Recommend REST or GraphQL, PostgreSQL vs MongoDB, and JWT vs session auth — with a one-line reason for each, optimized for shipping speed over long-term scale.
Prompt 2 · Repo scaffold
Generate a monorepo folder structure for a React + Express + PostgreSQL/Prisma e-commerce app. Include client/, server/, shared/ (types), and config for environment variables. List each folder's purpose in one line.

Decision tree — pick your data layer

Do your products have complex, varying attributes (many variant types, custom fields per category)?

Best practices

✓Version your API from day one (/api/v1/...) — cheap now, painful to retrofit.
✓Keep shared TypeScript types in one place if client and server both use TS.
✓Design the auth flow before building any protected route.

Common mistakes

✗Choosing GraphQL for a simple catalog because it feels "more modern."
✗Storing prices as floats instead of integers (cents) — causes rounding bugs at checkout.
✗Hardcoding secrets instead of setting up .env from the start.

Expected output

A system architecture diagram, a decided DB/ORM/auth stack, and an initialized repo with folder structure and env config.

Efficiency tip

Ask your AI tool to generate the Prisma schema directly from your Stage 1 data model — it's usually 80% correct and saves the tedious first draft.

03 · UI/UX & Prototyping

⏱ 4–6 daysOutput: Wireframes + design system

Design the storefront, cart, and checkout flow before writing React components — checkout UX mistakes are the single biggest cause of cart abandonment.

Objectives

  • Wireframe the core screens: home/catalog, product detail, cart, checkout, order confirmation, admin.
  • Establish a lightweight design system: colors, type scale, spacing, component variants.
  • Design the checkout flow to minimize steps and clearly show progress.

Tasks

  • Wireframe 6 core screens (home, PDP, cart, checkout, confirmation, admin)
  • Define design tokens: color palette, type scale, spacing scale
  • Design mobile-first responsive breakpoints
  • Prototype the checkout flow specifically (steps, error states, empty states)

Best AI tools

Figma (First Draft AI)
Generates editable, real Figma frames from a text prompt — best starting point when you need actual design files, not just a picture.
Alt: Uizard (faster but less editable)
v0 by Vercel
Generates working React + Tailwind UI directly from a prompt — skips the "design file → code" translation step entirely.
Alt: Claude Artifacts (good for quick interactive mockups)
Midjourney / DALL·E
Useful only for mood-boarding visual direction (not for UI itself) — generate lifestyle imagery references for your brand.
Alt: skip if you already have a clear visual direction

Prompt examples

Prompt 1 · Component-ready UI
Design a product detail page for a [niche] e-commerce store using React and Tailwind CSS. Include an image gallery, variant selector (size/color), price, add-to-cart button, and a collapsible details/shipping section. Mobile-first, clean and minimal.
Prompt 2 · Checkout flow
Design a 3-step checkout flow (shipping → payment → review) for an e-commerce site. Show a persistent order summary sidebar, inline validation errors, and a clear progress indicator. Optimize for minimizing abandonment.

Best practices vs. common mistakes

DoDon't
Show real product photos/placeholder content while designingDesign with "Lorem Ipsum" — hides real layout problems
Design empty-cart and error states explicitlyOnly design the "happy path" screens
Keep checkout to 3 steps or fewerSplit checkout across 5+ pages

Expected output

A Figma file or v0-generated component set covering all core screens, plus a documented design system (colors, type, spacing).

Efficiency tip

Generate UI directly in v0/Claude with Tailwind classes — you can paste the output almost directly into your React project in Stage 4, skipping a manual "translate design to code" pass.

04 · Frontend Build (React)

⏱ 2–3 weeksOutput: Working storefront UI

Build the React app: routing, state management for cart/auth, and componentized screens wired to (initially mocked) API calls.

Objectives

  • Set up routing (product listing, PDP, cart, checkout, account, admin).
  • Implement cart state (Context API, Zustand, or Redux Toolkit) that persists across sessions.
  • Build reusable components: ProductCard, VariantSelector, CartDrawer, CheckoutForm.

Tasks

  • Set up Vite + React Router + Tailwind
  • Build cart state management with localStorage persistence
  • Build product listing + filtering/search UI
  • Build product detail page with variant selection
  • Build cart drawer/page and checkout form components
  • Wire components to mock/placeholder API responses

Best AI tools

Cursor
Best for sustained React feature-building — understands your whole codebase, not just isolated snippets, so components stay consistent.
Alt: GitHub Copilot (great inline autocomplete, weaker at multi-file edits)
Claude Code
Handles multi-file refactors well (e.g., "extract cart logic into a custom hook across 6 components") from a terminal workflow.
Alt: Windsurf (similar agentic coding experience)
v0 by VercelFree tier
Fastest way to generate a new component from scratch when starting a screen you haven't built yet.
Alt: build manually with Copilot autocomplete for full control

Prompt examples

Prompt 1 · Cart hook
Write a React custom hook `useCart` using Context API that supports addItem, removeItem, updateQuantity, and clearCart, persists state to localStorage, and recalculates the subtotal on every change. Include TypeScript types.
Prompt 2 · Refactor request
Here's my ProductCard, ProductGrid, and Cart components: [paste code]. Refactor to remove duplicated price-formatting logic into a shared utility function, without changing any visual behavior.

Best practices

✓Build against mock API responses first — don't block frontend work on the backend being done.
✓Keep cart/price math in one tested utility, never scattered across components.
✓Review every AI-generated component for accessibility (labels, focus states) before moving on.

Common mistakes

✗Letting AI-generated components pile up without reading the code — debugging becomes guesswork later.
✗Prop-drilling cart state instead of using Context/Zustand.
✗Skipping loading and error states "for now" — they never get added later.

Expected output

A functioning React storefront — browsing, filtering, cart, and checkout UI — running against mock data, fully responsive.

Efficiency tip

Use Cursor's "chat with codebase" to ask it to find every place a piece of state is used before refactoring — much faster than manually grepping across files.

05 · Backend Build (Node.js)

⏱ 2–3 weeksOutput: REST API + database

Build the Express API, database models, and business logic — products, cart, orders, auth — that the React app will consume for real.

Objectives

  • Implement CRUD endpoints for products, categories, and inventory.
  • Build authentication (signup/login/refresh) and protected admin routes.
  • Implement order creation logic with inventory decrement and validation.

Tasks

  • Set up Express server, middleware, and error handling
  • Implement Prisma/DB models from the Stage 2 schema
  • Build product/category CRUD endpoints
  • Build auth: register, login, JWT refresh, password reset
  • Build cart-to-order conversion logic with inventory checks
  • Add input validation and rate limiting

Best AI tools

Claude Code
Strong at reasoning through backend business logic (order validation, race conditions on inventory) rather than just generating boilerplate.
Alt: Cursor for inline editing within Express route files
GitHub Copilot
Fast for repetitive CRUD endpoint boilerplate once the pattern is established for one resource.
Alt: Cody (Sourcegraph) for larger codebases
Postman AI
Generates test requests and example payloads from your route definitions — speeds up manual API testing during dev.
Alt: Insomnia (manual, no AI, but lightweight)

Prompt examples

Prompt 1 · Order logic
Write an Express route handler for POST /api/orders that: validates cart items against current inventory, uses a database transaction to decrement stock and create the order atomically, and returns a 409 if any item is out of stock. Use Prisma.
Prompt 2 · Auth middleware
Write Express middleware that verifies a JWT from the Authorization header, attaches the decoded user to req.user, and returns 401 on invalid/expired tokens. Include a separate requireAdmin middleware that checks req.user.role.

Best practices vs. common mistakes

DoDon't
Use DB transactions for order creation + inventory updatesUpdate inventory and create the order as separate, non-atomic writes
Validate all inputs server-side, even if validated client-side tooTrust the frontend's validation alone
Hash passwords with bcrypt/argon2, never store plaintextRoll your own crypto or skip hashing "temporarily"

Expected output

A running Express API with authenticated routes, a real database, and order logic that correctly handles stock — testable via Postman independent of the frontend.

Efficiency tip

Ask Claude/Cursor to generate the first CRUD resource fully (routes, controller, validation), then reuse it as the pattern for every other resource — much faster than generating each one from scratch.

06 · Payments & Integrations

⏱ 1–2 weeksOutput: Live checkout, email, media

Connect the pieces that make it a real store: payment processing, transactional email, and image hosting/optimization.

Objectives

  • Integrate a payment provider with both client-side and server-side (webhook) handling.
  • Set up transactional email for order confirmation, shipping updates, password reset.
  • Set up image upload/optimization for product photos (CDN + resizing).

Tasks

  • Integrate Stripe Checkout or Payment Intents on frontend + backend
  • Implement Stripe webhook handler for payment confirmation
  • Set up transactional email (order confirmation, shipping, password reset)
  • Set up image upload pipeline (e.g., Cloudinary/S3) with resizing
  • Test full purchase flow end-to-end in Stripe test mode

Best AI tools

Claude / ChatGPT
Best for reasoning through Stripe's webhook signature verification and idempotency correctly — an area with real security consequences if done wrong.
Alt: Stripe's own docs + AI chat combined (verify against official docs)
Cursor / Copilot
Fast for wiring up SDK boilerplate (Stripe.js, SendGrid/Resend clients) once the integration pattern is decided.
Alt: manual SDK setup following official quickstarts
Resend / Postmark AI templates
Generates clean transactional email templates (HTML+text) faster than hand-coding email-safe HTML.
Alt: React Email (component-based email templates)

Prompt examples

Prompt 1 · Webhook handler
Write an Express webhook handler for Stripe's checkout.session.completed event. Verify the webhook signature using the raw request body, then mark the corresponding order as "paid" in the database. Include proper error handling for signature verification failure.
Prompt 2 · Email template
Write a React Email template for an order confirmation email showing order number, itemized list with images, subtotal/shipping/total, and estimated delivery date. Keep it email-client-safe (no flexbox reliance).

Comparison — payment providers

ProviderBest forFeesNote
StripeMost flexibility, best docs~2.9% + 30¢Default recommendation for custom builds
RazorpayIndia-focused stores, UPI support~2%Better local payment methods for Indian customers
PayPalBuyer trust/familiarity~2.9%+ fixed feeGood as a secondary option, not primary

Expected output

A working end-to-end purchase: card payment processed, order marked paid via webhook, confirmation email sent, product images loading from CDN.

Efficiency tip

Always test webhooks locally with the Stripe CLI (`stripe listen --forward-to`) before deploying — catching signature/timing bugs in production is far more painful.

07 · Testing & QA

⏱ 1 weekOutput: Test suite + bug list

Catch checkout and payment bugs before real customers do. Focus test effort where money moves: cart math, order creation, and payment webhooks.

Objectives

  • Unit test cart/pricing logic and order validation.
  • Integration test the checkout API flow, including failure cases (declined card, out of stock).
  • Manual/exploratory test across devices and browsers.

Tasks

  • Write unit tests for cart totals, discounts, and tax calculations
  • Write integration tests for the order creation endpoint (success + failure paths)
  • Test Stripe webhook handling with simulated events
  • Cross-browser/device manual QA pass on checkout flow
  • Run a basic accessibility audit (keyboard nav, screen reader labels)

Best AI tools

Claude Code / Cursor
Can generate a full Jest/Vitest test suite from existing function signatures, including edge cases you might not think of.
Alt: Copilot for individual test-case autocomplete
Playwright + AI codegen
Generates end-to-end browser tests for the full checkout flow from a recorded session or plain description.
Alt: Cypress (similar, slightly different API)
axe DevTools / Stark AI
Automated accessibility scanning with AI-suggested fixes for contrast, labeling, and focus order issues.
Alt: manual screen-reader pass with VoiceOver/NVDA

Prompt examples

Prompt 1 · Test generation
Here is my calculateCartTotal function: [paste code]. Write a Vitest test suite covering: empty cart, single item, multiple items with quantities, applied discount code, and free-shipping threshold edge cases.
Prompt 2 · E2E scenario
Write a Playwright test that: adds a product to cart, proceeds to checkout, fills in test shipping info, completes payment with Stripe's test card 4242 4242 4242 4242, and asserts the order confirmation page shows the correct order total.

Best practices

✓Prioritize testing anything involving money or inventory over UI polish tests.
✓Test the "out of stock at checkout" race condition explicitly.
✓Run the full flow on a real mobile device, not just devtools emulation.

Common mistakes

✗Only testing the happy path (successful payment, item in stock).
✗Trusting AI-generated tests without reading what they actually assert.
✗Skipping accessibility checks because "it's just an MVP."

Expected output

A test suite covering cart/order logic and the critical checkout path, plus a prioritized bug list from manual QA.

Efficiency tip

Have AI generate tests directly from your actual function code (not from a description) — it catches real edge cases in your logic rather than generic ones.

08 · Deployment & DevOps

⏱ 2–4 daysOutput: Live production app

Ship it. Set up hosting, environment secrets, a database in production, and basic monitoring before pointing a domain at it.

Objectives

  • Deploy the React frontend and Node backend to production hosting.
  • Move to a production database with backups configured.
  • Set up error monitoring and uptime checks.

Tasks

  • Deploy frontend (Vercel/Netlify) with production env vars
  • Deploy backend (Render/Railway/Fly.io) with production env vars
  • Provision production database with automated backups
  • Point custom domain + SSL, switch Stripe to live mode
  • Set up error monitoring (Sentry) and uptime alerts

Best AI tools

Claude / ChatGPT
Best for debugging deployment-specific errors (CORS, env var mismatches, build failures) by pasting logs directly.
Alt: search the exact error text first, then AI for synthesis
Cursor / Copilot
Generates CI/CD config (GitHub Actions) and Dockerfiles from a description of your stack.
Alt: hosting platform's own AI setup wizard, if offered

Prompt examples

Prompt 1 · CI/CD
Write a GitHub Actions workflow that runs on push to main: installs dependencies, runs the test suite, and if tests pass, deploys the client to Vercel and the server to Render. Fail the deploy if any test fails.
Prompt 2 · Debugging
I'm getting this error when deploying my Express app to Render: [paste error log]. My app works locally. What's the likely cause and how do I fix it?

Comparison — hosting for the Node API

PlatformBest forFree tier
RailwayFastest setup, good DX for solo devsLimited, usage-based
RenderSimple, predictable pricingYes, with cold starts
Fly.ioMore control, global edge deployYes, limited resources

Expected output

A live, publicly accessible store on a custom domain, processing real payments, with error monitoring in place.

Efficiency tip

Deploy early and often — even in Stage 4 — to a staging environment. Catching deployment issues incrementally is far faster than debugging them all at once at the end.

09 · Growth & Maintenance

⏱ OngoingOutput: Analytics + iteration loop

Launch is the start, not the finish. Set up analytics, monitor real usage, and build a lightweight loop for iterating based on actual customer behavior.

Objectives

  • Track key funnel metrics: product views, add-to-cart rate, checkout completion rate.
  • Set up SEO basics for organic discovery.
  • Build a lightweight process for triaging bugs and feature requests post-launch.

Tasks

  • Set up analytics (GA4 or Plausible) with funnel event tracking
  • Add basic SEO: meta tags, sitemap, structured data for products
  • Set up a bug/feature backlog with a weekly triage cadence
  • Review checkout drop-off data monthly and prioritize fixes

Best AI tools

GA4 + Claude/ChatGPT
Paste exported analytics data and ask for funnel drop-off analysis and prioritized hypotheses — faster than manually reading dashboards.
Alt: Plausible (privacy-friendly, simpler data export)
Claude / ChatGPT for SEO
Generates product meta descriptions and structured data (schema.org Product markup) at scale from your product data.
Alt: Surfer SEO for deeper keyword-driven content work

Prompt examples

Prompt 1 · Funnel analysis
Here's my funnel data for the last 30 days: [paste numbers — views, add-to-cart, checkout starts, purchases]. Identify the biggest drop-off point and suggest 3 specific, testable hypotheses for why it's happening.
Prompt 2 · Structured data
Generate schema.org Product JSON-LD markup for this product: [name, price, description, image URL, availability]. Format it ready to paste into a React Helmet/Head component.

Expected output

A live funnel dashboard, basic SEO in place, and a running backlog of prioritized post-launch improvements.

Efficiency tip

Review just one metric weekly — checkout completion rate — rather than trying to optimize everything at once post-launch.

Workflow Summary & Recommended Stack

Workflow summary

Nine stages take you from a one-paragraph idea to a live, monitored e-commerce store: scope and data model first, then architecture, then design, then parallel-ish frontend/backend builds, then the integrations that make it a real store (payments, email, media), then testing focused on money-critical paths, then deployment, then an ongoing growth loop. The through-line: use AI to compress research and boilerplate, but keep human judgment on data modeling, checkout UX, and anything touching payments or auth.

Recommended AI stack

Claude (Sonnet/Opus)Planning, architecture reasoning, code review
Cursor or Claude CodeDay-to-day feature building, refactors
v0 by VercelUI scaffolding straight to React + Tailwind
GitHub CopilotInline autocomplete for repetitive code
Playwright + AI codegenEnd-to-end checkout testing
ChatGPT/Claude + GA4Post-launch funnel analysis

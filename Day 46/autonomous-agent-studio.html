How the stop-check governs the loop

Every round the same three agents run in sequence — Evaluator, then Critic, then Improver — and the Improver's rewrite becomes next round's input to the Evaluator. That return arrow (Improver → Evaluator) is the actual loop: there is no fixed number of passes. After each Evaluator score is recorded, the orchestrator checks, in order: (1) plateau — did the score move by less than 0.3 for two rounds running; (2) threshold — did the score cross the target set at interview; (3) hard cap — a safety ceiling of 8 rounds that should rarely be the real reason a run ends. Whichever fires first ends the loop and routes the latest draft to the Final Reviewer, whose job is only to package the result — it never re-scores or re-writes.

Agent responsibilities

  • Planner — turns the brief into a concrete outline: angle, structure, key points.
  • Executor — writes the first full draft strictly from the Planner's outline.
  • Evaluator — scores the current draft 0–10 against the quality rubric, every round, from scratch.
  • Critic — reads the Evaluator's score and reasoning, then names the 2–4 sharpest weaknesses.
  • Improver — rewrites the full draft addressing the Critic's points, preserving what scored well.
  • Memory Manager — records what changed and why, so future rounds don't re-break fixed issues.
  • Final Reviewer — packages the winning draft and states the exact reason the loop stopped.

Extension ideas

  • Add a Safety Monitor agent that screens drafts for claims, brand risk, or compliance before Final Review.
  • Run Evaluator twice per round (rubric-only vs. reader-simulation) and average the two scores.
  • Persist memory across separate briefs so recurring critique patterns inform future Planner outlines.
  • Add a human-in-the-loop approval gate between Final Reviewer and publish.
  • Swap the Executor/Improver pairing for parallel drafts (A/B) evaluated head-to-head each round.

Prompts to go further
